# AI医生数据清洗结果（试行版）

## 1. 输入与目标

- 原始输入：`../对话数据/对话数据.txt`
- 目标角色：AI 眼科医生
- 对话对象：医药代表
- 目标：让 AI 医生以自然、专业、谨慎的方式了解产品与证据，不因宣传性表述直接认可产品。

原始目录中的两份文本内容几乎完全相同，本次只以 `对话数据.txt` 作为来源，避免重复放大。

## 2. 输出文件

### `examples.jsonl`

用于 few-shot 示例库，教模型“怎么回复”。每条包含：

- 对话阶段和医药代表意图；
- AI 医生下一步行为；
- 用于系统检索的行为标签；
- 医药代表输入和重写后的理想医生回复；
- 原始对话追溯信息。

标签用于选择示例，默认不原样发给模型。运行时按 `stage + representative_intent + doctor_action + topic` 选择 3–5 条互补示例。

### `knowledge_candidates.jsonl`

用于医学知识候选库，教模型“事实是什么”。当前内容只是从对话中抽取的宣称，不是已核验医学事实。

所有记录均为：

```json
{"review_status":"pending_medical_review","usable_for_generation":false}
```

必须由医学/法规人员核对原始文献、说明书、适用地区和版本后，才能改为可检索生成。

### `evaluation.jsonl`

固定评测集。不参与 few-shot 选择、提示词调整或训练，用于比较不同方案的角色稳定性、证据意识、自然度和安全性。

## 3. 运行时组装方式

```text
固定系统提示词
+ 最新会话状态
+ 3–5条相关且行为互补的示例
+ 本轮经过医学审核的知识检索结果
+ 必要的真实对话历史
+ 最新医药代表发言
```

示例选择不要只做文本相似度检索。建议先根据会话状态过滤，再按语义相似度排序，并限制同一 `doctor_action` 最多两条，防止回复方式单一。

## 4. 审核状态

- `rewritten_review_required`：已按 AI 医生目标重写，需产品和医学人员联合审核后上线。
- `pending_medical_review`：只完成知识去重和结构化，未证实真实性。
- `approved`：建议只由有权审核人员设置。

## 5. 下一步

1. 医学人员先审核 `knowledge_candidates.jsonl`，补齐来源、版本、原文位置、适用范围和局限性。
2. 产品与医学人员共同审核 `examples.jsonl`，确认回复符合预期医生职称和实际沟通习惯。
3. 使用 `evaluation.jsonl` 同时测试“仅系统提示词”和“系统提示词 + 示例”。
4. 根据失败类型定向补充示例，不再成批复制高度相似的完整对话。
